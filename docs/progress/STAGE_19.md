## 1. Scope

Stage 19 turns the Windows image and Android debug build into distributable,
verifiable release artifacts:

- Per-user Windows MSI and portable ZIP.
- Signed Android APK and AAB from one release pipeline.
- SHA-256 checksums and a machine-readable release manifest.
- Performance measurement for startup, memory, idle CPU, and package size.
- A compatibility matrix with verified, built-but-unrun, and unsupported states.
- Release notes, upgrade/rollback policy, signing policy, and reproducibility
  limits.
- Accessibility and localization review.

The stage does not add a new product feature, an auto-updater, telemetry, or
crash reporting.

| Area | Change |

The Windows installer is an MSI, not an Inno Setup EXE. ADR-0009 originally
specified Inno Setup; the Stage 19 amendment records that jpackage with WiX 3 was
used because it is already part of the Compose Desktop toolchain, installs
per-user without elevation, and supports the stable upgrade UUID. The interactive
uninstall data prompt remains a known gap.

## 3. Release pipeline

`scripts/package-release.ps1`:

1. Refuses a dirty tree unless `-AllowDirty` is passed.
2. Builds Windows and Android native cores with `--locked`, verifying exported
   symbols.
3. Downloads WiX with a pinned SHA-256 and adds it to `PATH`.
4. Builds Android release APK/AAB and Windows app image/MSI.
5. Signs with the supplied Android keystore and Windows certificate.
6. Copies artifacts to `dist/<version>` with stable product names.
7. Writes `SHA256SUMS` and `release-manifest.json`.
8. Runs `verify-release.ps1` with signature enforcement.

`scripts/verify-release.ps1` independently checks sizes and hashes against the
manifest and checksum file, APK and AAB signatures, MSI signer presence, and the
native payloads inside the APK and portable ZIP.

| Criterion | Status |
|---|---|

| Performance targets are met on agreed baseline devices | Windows targets met on the available machine. Android targets unmeasured; no baseline device was available. |
| Install, update and uninstall work on both platforms | Windows install, upgrade, and uninstall verified. Android install/update/uninstall not executed. |

Stage 19 therefore delivers the release engineering and Windows evidence, but it
does **not** satisfy the exit criteria for a public Android release. The stage is
recorded as complete with explicit gaps rather than claiming evidence that was
not collected.

## 7. Failure evidence and fixes

- `-PemberVersion=1.2.3` initially reached Gradle as `1` because PowerShell
  parsed the unquoted argument. Passing `"-PemberVersion=$Version"` from the
  script fixed it.
- MSI version validation rejected the root package version path. The Windows
  package version is now set explicitly, and the script enforces MSI segment
  limits.
- PowerShell 5.1 did not splat a native argument array (`@lockArgs`) correctly
  and cargo received a bare `-`. The script now builds an explicit argument array
  and splats that.
- Signing the app image failed because jpackage marks `Ember.exe` read-only. The
  signing path clears the read-only flag and restores it afterward.
- `apksigner.bat` returned -1 to PowerShell even when verification succeeded.
  Verification now invokes it through `cmd.exe`, checks the `Verifies` output and
  exit code, and does the same for the `jarsigner` warnings.
- The portable ZIP check failed because `Compress-Archive` writes backslash entry
  names. The check accepts both separators.
- Reinstalling the same MSI from a different path triggered a repair failure
  (1603) because an older 0.1.0 install was still registered. Uninstalling the
  stale product first produced a clean install; the installed-file and launch
  evidence comes from that clean run.
- An early app image contained duplicate `nexus_core.dll` copies left by the
  previous manual staging. The Gradle `stageNativeCore` task now owns the file,
  and the final image contains one copy under `app/resources`.
- Android `--strip-unneeded` removed symbols the verification step reads.
  `--strip-debug` keeps exported symbols while removing debug sections.

## 9. Decisions

- Releases are test-signed until organization-owned signing material exists; the
  pipeline fails closed without signing configuration.
- The Windows installer is a per-user MSI. No elevation and a stable upgrade UUID
  are required. The uninstall data prompt is deferred until the packaged app
  stores core data.
- Android release signing is environment-driven. No keystore or password is
  committed.
- The portable ZIP is an unsigned container with a signed executable inside; it
  is not described as a signed artifact.
- Crash reporting and telemetry remain absent. Any future reporter needs explicit
  opt-in, local preview, and redaction.
- No chunk, hash, or index tuning was made without a realistic workload.
